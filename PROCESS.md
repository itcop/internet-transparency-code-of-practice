# How this code of practice is developed

## The short version

In the open, in this repository. Anyone may comment. **Commenting places nobody
on any list, and there is no membership.**

## Why it is done this way

The code asks implementers to publish the material a decision will be made
against, at a location that resolves, before the individual is identified. A
code of practice written in private and published as a finished thing would not
meet that requirement itself.

So the change record is the commit history, the authorship is the commit
authorship, and what is unresolved is written below rather than left to be
inferred.

## What is settled

- **The subject.** Regulatory capacity: authorities are asked to determine
  whether people were properly informed, and the evidence needed to determine it
  does not exist in a form anyone can inspect, reproduce or share.
- **The four requirements** in the README.
- **The reuse terms for the white paper**: CC BY 4.0 with 0PN Machine Reuse
  Terms 1.0, `0pn-mrt-1.0-2026-08-31`, reservation at `/.well-known/tdmrep.json`.
- **This draft does not speak for any standards body.** Where it differs from
  work in ISO/IEC JTC 1/SC 44, SC 27/WG 5, or the Council of Europe, they govern.

## What is open

- The nine levels, and which of them earn a page of their own.
- Whether the four requirements are the right four, which is what the
  stakeholder survey asks supervisory authorities.
- Whether the code text and the site code carry the same reuse terms.
- How conformance would be assessed, and by whom. Nothing here proposes a
  certification scheme, and self-assertion is not conformity assessment.

## How to comment

**Open an issue** for a specific change to the text: what it says now, what it
should say, and why.

**Start a discussion** for a question, an objection to the approach, or anything
that is not yet a proposed change.

**Send an email** to info@tcieg.org if you would rather not comment in public.
A comment made in private is not published with a name attached to it.

## What happens to a comment

It is read. If it changes the draft, the change appears in the commit history
with a reference to the issue or discussion it came from. If it does not change
the draft, the reason is written in the thread rather than left unanswered.

## Who is listed anywhere

**Contributors**, meaning anyone whose proposed text is merged, appear in the
commit history. That is a consequence of using git and it is visible before
anyone contributes.

**Nobody else.** There is no member list, no supporter list, and no register of
organisations that have expressed interest. Reading this repository, opening an
issue, starting a discussion or sending an email places you on none of them,
because none of them exist.

**Supervisory authorities in particular.** The stakeholder survey is a separate
instrument with its own undertaking: the aggregate is published, no individual
response is attributed, and any authority may decline to be counted. Engaging
with this repository does not alter that undertaking in either direction.

**Organisations that adopt the code** may choose to publish a self-asserted
transparency listing through the 0PN directory, which is operated separately and
under its own terms. A listing there is self-declared and is not verified,
audited or certified. It is not membership of anything, and it is not an
endorsement by this code of practice.
